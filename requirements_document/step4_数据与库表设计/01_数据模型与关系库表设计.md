## 一、公共字段与命名规范

### 1.1 公共字段（强制）

- 业务实体表必须含四公共字段：`id`、`create_time`、`update_time`、`is_delete`；
- `id UUID DEFAULT uuid_generate_v4() PRIMARY KEY`；
- `create_time/update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW()`，时区 Asia/Shanghai，update 触发器自动赋值；
- `is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))`，'0' 未删 / '1' 已删，逻辑删除不走物理删除；
- append-only 日志表（dialog_turns / intent_tags / audit_logs / llm_call_logs / etl_task_logs / complaint_agent_logs / kb_search_logs）仅含 `id` + `create_time`（kb_search_logs 另含 is_delete 以对齐 DD-03 已有列，写入失败不阻断检索主流程），不参与业务更新；
- dw 层特征宽表 `dw.ads_user_features` 以 `case_id` 为 PK，仅含 `etl_processed_at`（ETL 覆盖写入），不含 `id/create_time/is_delete`，属于中台架构例外。

### 1.2 命名与类型

- 表名 snake*case 复数，业务库 `public.<表>`，中台 `dw.<层>*<主题>\_<表>`；
- 主键统一 UUID；时间统一 `TIMESTAMP WITH TIME ZONE`；枚举用 `VARCHAR + CHECK IN(...)`，不用 BOOLEAN；
- JSONB 承载复杂嵌套，COMMENT 注明 schema；外键 `REFERENCES ... ON DELETE CASCADE/RESTRICT`。

### 1.3 schema 划分

- `public`：业务事务表（**25 张**，与 §2.1 清单逐行一致）；
- `dw`：数据中台离线分层表（ods/dwd/dws/ads，8 张）；
- 双 schema 共用 PostgreSQL 15 单实例，ClickHouse 不引入 MVP。

## 三、完整 DDL（单一事实源）

```sql
-- ============================================================
-- 电话催收AI系统 核心数据表 DDL（规范层 v1.0）
-- PostgreSQL 15+，public + dw 双 schema 单实例
-- 公共字段：id / create_time / update_time / is_delete
-- ============================================================
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- ============================================================
-- 1. 案件表
-- ============================================================
CREATE TABLE cases (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    case_number VARCHAR(50) UNIQUE NOT NULL,
    customer_name VARCHAR(100) NOT NULL,
    phone_encrypted VARCHAR(255) NOT NULL,
    phone_hash VARCHAR(64) NOT NULL,
    id_card_hash VARCHAR(64),
    overdue_amount DECIMAL(12,2) NOT NULL,
    overdue_days INT NOT NULL,
    account_stage VARCHAR(10) NOT NULL CHECK (account_stage IN ('M0','M1','M2','M3')),
    case_status VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (case_status IN ('pending','processing','paid','bad_debt','lost')),
    stop_call_status VARCHAR(20) NOT NULL DEFAULT 'callable' CHECK (stop_call_status IN ('callable','stop_requested','stopped','permanent_stop','reduced_intensity')),
    assigned_to UUID REFERENCES users(id) ON DELETE RESTRICT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_cases_case_number ON cases(case_number);
CREATE INDEX idx_cases_phone_hash ON cases(phone_hash);
CREATE INDEX idx_cases_account_stage ON cases(account_stage);
CREATE INDEX idx_cases_case_status ON cases(case_status);
CREATE INDEX idx_cases_stop_call_status ON cases(stop_call_status);
CREATE INDEX idx_cases_assigned_to ON cases(assigned_to);
COMMENT ON TABLE cases IS '逾期案件主表';
COMMENT ON COLUMN cases.phone_encrypted IS 'AES-256-GCM 加密存储，展示时脱敏';
COMMENT ON COLUMN cases.stop_call_status IS '停止致电状态（红线3 落库）：callable=可外呼 / stop_requested=客户表达停止致电待确认 / stopped=已停止 / permanent_stop=永久停止 / reduced_intensity=投诉成立降强度；中文「外呼拦截/人工复核/策略分支」不是本列枚举（对照 step1/03）；外呼调度与分案分流发呼前强制校验';

-- ============================================================
-- 2. 用户与坐席表
-- ============================================================
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    real_name VARCHAR(50) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('admin','supervisor','agent','qc_reviewer','ai_trainer')),
    agent_skills JSONB DEFAULT '[]'::jsonb,
    status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled','locked')),
    last_login_at TIMESTAMP WITH TIME ZONE,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_status ON users(status);
COMMENT ON TABLE users IS '系统用户与坐席主表，承载 RBAC 角色与坐席技能画像';
COMMENT ON COLUMN users.password_hash IS 'bcrypt 哈希，cost factor=12，禁止明文存储';

-- ============================================================
-- 3. 通话记录表（核心闭环）
-- ============================================================
CREATE TABLE call_records (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) UNIQUE NOT NULL,
    trace_id VARCHAR(100),
    case_id UUID NOT NULL REFERENCES cases(id) ON DELETE CASCADE,
    agent_id UUID REFERENCES users(id) ON DELETE SET NULL,
    call_type VARCHAR(20) NOT NULL CHECK (call_type IN ('ai','human')),
    call_status VARCHAR(20) NOT NULL CHECK (call_status IN ('ringing','connected','no_answer','failed','completed')),
    start_time TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    end_time TIMESTAMP WITH TIME ZONE,
    duration_seconds INT DEFAULT 0,
    result VARCHAR(20) CHECK (result IN ('ptp','refused','no_answer','lost','escalated','completed')),
    sentiment_score FLOAT CHECK (sentiment_score IS NULL OR (sentiment_score >= 0 AND sentiment_score <= 1)),
    record_url TEXT,
    summary TEXT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_call_records_session_id ON call_records(session_id);
CREATE INDEX idx_call_records_case_id ON call_records(case_id);
CREATE INDEX idx_call_records_agent_id ON call_records(agent_id);
CREATE INDEX idx_call_records_start_time ON call_records(start_time DESC);
COMMENT ON TABLE call_records IS '全量通话记录，AI 和人工统一入库';
COMMENT ON COLUMN call_records.session_id IS '通话业务键，API 路径 {session_id} 用此字段。≠ 投诉研判 judgment_session_id';
COMMENT ON COLUMN call_records.record_url IS '录音对象存储 URL，非独立实体。不设 recording_id/audio_id/file_id；业务关联键=session_id 或 call_records.id（事件/HTTP 称 call_id）。质检不碰录音文件流';
COMMENT ON COLUMN call_records.id IS '行主键 UUID；对外事件键名 call_id，禁止用 session_id 冒充';
COMMENT ON COLUMN call_records.summary IS '通话摘要，客户可能自述身份证/手机号/银行卡号，落库前须经 common/security/mask.py 脱敏（PII 打码），原始敏感内容不入库；脱敏不可逆损失需在审计/训练用场景单独授权（原始走 AES-256-GCM 加密 + 角色授权解密）';

-- ============================================================
-- 4. 对话轮次表（append-only）
-- ============================================================
CREATE TABLE dialog_turns (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) NOT NULL REFERENCES call_records(session_id) ON DELETE CASCADE,
    turn_number INT NOT NULL,
    speaker VARCHAR(10) NOT NULL CHECK (speaker IN ('ai','user')),
    text TEXT NOT NULL,
    reasoning_encrypted TEXT,
    confidence FLOAT CHECK (confidence IS NULL OR (confidence >= 0 AND confidence <= 1)),
    intent_label VARCHAR(30),
    latency_ms INT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_dialog_turns_session_id ON dialog_turns(session_id);
CREATE INDEX idx_dialog_turns_create_time ON dialog_turns(create_time DESC);
COMMENT ON TABLE dialog_turns IS '每通电话逐轮对话，append-only，用于审计和模型训练';
COMMENT ON COLUMN dialog_turns.speaker IS '通话落库枚举 ai|user。质检入站必须映射：ai→agent，人工坐席话术→agent，user 保持 user；禁止第三值';
COMMENT ON COLUMN dialog_turns.reasoning_encrypted IS 'AI 决策推理过程，AES-256 加密存储，仅 role=admin 可解密';
COMMENT ON COLUMN dialog_turns.text IS '对话正文，客户可能自述身份证/手机号/银行卡号，落库前须经 common/security/mask.py 脱敏（PII 打码），原始敏感内容不入库；如需保留原始用于训练，走 AES-256-GCM 加密存储 + 角色授权解密，禁止明文落库';

-- ============================================================
-- 5. 质检记录表
-- ============================================================
CREATE TABLE qc_records (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) NOT NULL UNIQUE REFERENCES call_records(session_id) ON DELETE CASCADE,
    case_id UUID REFERENCES cases(id) ON DELETE SET NULL,
    agent_id UUID REFERENCES users(id) ON DELETE SET NULL,
    compliance_score INT NOT NULL CHECK (compliance_score BETWEEN 0 AND 100),
    risk_level VARCHAR(10) NOT NULL CHECK (risk_level IN ('low','medium','high')),
    qc_result VARCHAR(20) NOT NULL CHECK (qc_result IN ('compliant','violation','pending_review')),
    grade VARCHAR(20) CHECK (grade IN ('EXCELLENT','PASS','WARNING','SERIOUS')),
    qc_status VARCHAR(20) NOT NULL DEFAULT 'DONE' CHECK (qc_status IN ('DONE','PENDING_REVIEW','REVIEWED','PARTIAL')),
    high_count INT NOT NULL DEFAULT 0,
    med_count INT NOT NULL DEFAULT 0,
    low_count INT NOT NULL DEFAULT 0,
    violations JSONB,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
```

## 六、Alembic 迁移约束

- 所有表结构变更必须经 `alembic revision --autogenerate` 生成迁移脚本，Code Owner 双人评审后 `alembic upgrade`，禁手动 DDL；
- 迁移脚本含 `upgrade()` 与 `downgrade()`，必须可回滚；数据迁移与结构迁移分脚本提交；
- 生产迁移窗口 02:00–05:00，大表加列分两步（先加可空列 → 回填 → 改非空）；
- 验收：`alembic upgrade head` 零错误；pytest 覆盖率≥85%；ORM 与 DDL 反射逐一对应；Pydantic Literal 与 CHECK IN 双向对齐脚本通过；Milvus kb_vectors 可写入检索 1024 维；三张强制 DWS 表 ETL 可产出。
