## 一、公共字段与命名规范

### 1.1 公共字段（强制）

- 业务实体表必须含四公共字段：`id`、`create_time`、`update_time`、`is_delete`；
- `id UUID DEFAULT uuid_generate_v4() PRIMARY KEY`；
- `create_time/update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW()`，时区 Asia/Shanghai，update 触发器自动赋值；
- `is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))`，'0' 未删 / '1' 已删，逻辑删除不走物理删除；
- append-only 日志表（dialog_turns / intent_tags / audit_logs / llm_call_logs / etl_task_logs）仅含 `id` + `create_time`，不参与软删与更新；
- dw 层特征宽表 `features_user` 以 `case_id` 为 PK（引用 cases.id），仅含 `update_time`（ETL 覆盖写入），不含 `id/create_time/is_delete`，属于中台架构例外。

### 1.2 命名与类型

- 表名 snake*case 复数，业务库 `public.<表>`，中台 `dw.<层>*<主题>\_<表>`；
- 主键统一 UUID；时间统一 `TIMESTAMP WITH TIME ZONE`；枚举用 `VARCHAR + CHECK IN(...)`，不用 BOOLEAN；
- JSONB 承载复杂嵌套，COMMENT 注明 schema；外键 `REFERENCES ... ON DELETE CASCADE/RESTRICT`。

### 1.3 schema 划分

- `public`：业务事务表（19 张）；
- `dw`：数据中台离线分层表（ods/dwd/dws/ads，8 张）；
- 双 schema 共用 PostgreSQL 15 单实例，ClickHouse 不引入 MVP。

## 三、完整 DDL（单一事实源）

```sql
-- ============================================================
-- 电话催收AI系统 核心数据表 DDL（规范层 v1.0）
-- PostgreSQL 15+，public + dw 双 schema 单实例
-- 公共字段：id / create_time / update_time / is_delete
-- ============================================================
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- ============================================================
-- 1. 案件表
-- ============================================================
CREATE TABLE cases (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    case_number VARCHAR(50) UNIQUE NOT NULL,
    customer_name VARCHAR(100) NOT NULL,
    phone_encrypted VARCHAR(255) NOT NULL,
    phone_hash VARCHAR(64) NOT NULL,
    id_card_hash VARCHAR(64),
    overdue_amount DECIMAL(12,2) NOT NULL,
    overdue_days INT NOT NULL,
    account_stage VARCHAR(10) NOT NULL CHECK (account_stage IN ('M0','M1','M2','M3')),
    case_status VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (case_status IN ('pending','processing','paid','bad_debt','lost')),
    assigned_to UUID REFERENCES users(id) ON DELETE RESTRICT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_cases_case_number ON cases(case_number);
CREATE INDEX idx_cases_phone_hash ON cases(phone_hash);
CREATE INDEX idx_cases_account_stage ON cases(account_stage);
CREATE INDEX idx_cases_case_status ON cases(case_status);
CREATE INDEX idx_cases_assigned_to ON cases(assigned_to);
COMMENT ON TABLE cases IS '逾期案件主表';
COMMENT ON COLUMN cases.phone_encrypted IS 'AES-256-GCM 加密存储，展示时脱敏';

-- ============================================================
-- 2. 用户与坐席表
-- ============================================================
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    real_name VARCHAR(50) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('admin','supervisor','agent','qc_reviewer','ai_trainer')),
    agent_skills JSONB DEFAULT '[]'::jsonb,
    status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled','locked')),
    last_login_at TIMESTAMP WITH TIME ZONE,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_status ON users(status);
COMMENT ON TABLE users IS '系统用户与坐席主表，承载 RBAC 角色与坐席技能画像';
COMMENT ON COLUMN users.password_hash IS 'bcrypt 哈希，cost factor=12，禁止明文存储';

-- ============================================================
-- 3. 通话记录表（核心闭环）
-- ============================================================
CREATE TABLE call_records (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) UNIQUE NOT NULL,
    trace_id VARCHAR(100),
    case_id UUID NOT NULL REFERENCES cases(id) ON DELETE CASCADE,
    agent_id UUID REFERENCES users(id) ON DELETE SET NULL,
    call_type VARCHAR(20) NOT NULL CHECK (call_type IN ('ai','human')),
    call_status VARCHAR(20) NOT NULL CHECK (call_status IN ('ringing','connected','no_answer','failed','completed')),
    start_time TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    end_time TIMESTAMP WITH TIME ZONE,
    duration_seconds INT DEFAULT 0,
    result VARCHAR(20) CHECK (result IN ('ptp','refused','no_answer','lost','escalated','completed')),
    sentiment_score FLOAT CHECK (sentiment_score IS NULL OR (sentiment_score >= 0 AND sentiment_score <= 1)),
    record_url TEXT,
    summary TEXT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_call_records_session_id ON call_records(session_id);
CREATE INDEX idx_call_records_case_id ON call_records(case_id);
CREATE INDEX idx_call_records_agent_id ON call_records(agent_id);
CREATE INDEX idx_call_records_start_time ON call_records(start_time DESC);
COMMENT ON TABLE call_records IS '全量通话记录，AI 和人工统一入库';
COMMENT ON COLUMN call_records.session_id IS '业务级会话追踪主键，API 路径 {session_id} 用此字段';

-- ============================================================
-- 4. 对话轮次表（append-only）
-- ============================================================
CREATE TABLE dialog_turns (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) NOT NULL REFERENCES call_records(session_id) ON DELETE CASCADE,
    turn_number INT NOT NULL,
    speaker VARCHAR(10) NOT NULL CHECK (speaker IN ('ai','user')),
    text TEXT NOT NULL,
    reasoning_encrypted TEXT,
    confidence FLOAT CHECK (confidence IS NULL OR (confidence >= 0 AND confidence <= 1)),
    intent_label VARCHAR(30),
    latency_ms INT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_dialog_turns_session_id ON dialog_turns(session_id);
CREATE INDEX idx_dialog_turns_create_time ON dialog_turns(create_time DESC);
COMMENT ON TABLE dialog_turns IS '每通电话逐轮对话，append-only，用于审计和模型训练';
COMMENT ON COLUMN dialog_turns.reasoning_encrypted IS 'AI 决策推理过程，AES-256 加密存储，仅 role=admin 可解密';

-- ============================================================
-- 5. 质检记录表
-- ============================================================
CREATE TABLE qc_records (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) NOT NULL REFERENCES call_records(session_id) ON DELETE CASCADE,
    compliance_score INT NOT NULL CHECK (compliance_score BETWEEN 0 AND 100),
    risk_level VARCHAR(10) NOT NULL CHECK (risk_level IN ('low','medium','high')),
    qc_result VARCHAR(20) NOT NULL CHECK (qc_result IN ('compliant','violation','pending_review')),
    violations JSONB,
    reviewer_id UUID REFERENCES users(id) ON DELETE SET NULL,
    review_comment TEXT,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_qc_records_session_id ON qc_records(session_id);
CREATE INDEX idx_qc_records_qc_result ON qc_records(qc_result);
COMMENT ON TABLE qc_records IS '质检结果表，合规分=100-Σ扣分，下限 0';

-- ============================================================
-- 6. 意图标签表（append-only）
-- ============================================================
CREATE TABLE intent_tags (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id VARCHAR(100) NOT NULL REFERENCES call_records(session_id) ON DELETE CASCADE,
    turn_number INT,
    intent_type VARCHAR(30) NOT NULL CHECK (intent_type IN ('willing_to_pay','extension_request','financial_difficulty','stalling','rejection','anger','complaint','uncertain')),
    confidence FLOAT NOT NULL CHECK (confidence BETWEEN 0 AND 1),
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_intent_tags_session_id ON intent_tags(session_id);

-- ============================================================
-- 7. 知识库文档表
-- ============================================================
CREATE TABLE kb_documents (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    title VARCHAR(255) NOT NULL,
    category VARCHAR(50) NOT NULL CHECK (category IN ('regulation','script','case','other')),
    content TEXT NOT NULL,
    version INT DEFAULT 1,
    status VARCHAR(20) DEFAULT 'active' CHECK (status IN ('active','archived')),
    created_by UUID REFERENCES users(id) ON DELETE SET NULL,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_kb_documents_category ON kb_documents(category);
COMMENT ON TABLE kb_documents IS '知识库文档表，含政策/话术/案例/其他四分类';

-- ============================================================
-- 8. 知识库分块表
-- ============================================================
CREATE TABLE kb_chunks (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    doc_id UUID NOT NULL REFERENCES kb_documents(id) ON DELETE CASCADE,
    chunk_index INT NOT NULL,
    content TEXT NOT NULL,
    vector_id VARCHAR(100) NOT NULL,
    category VARCHAR(50),
    version INT DEFAULT 1,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1')),
    UNIQUE(doc_id, chunk_index)
);
CREATE INDEX idx_kb_chunks_doc_id ON kb_chunks(doc_id);
CREATE INDEX idx_kb_chunks_category ON kb_chunks(category);
CREATE UNIQUE INDEX idx_kb_chunks_vector_id ON kb_chunks(vector_id);
COMMENT ON TABLE kb_chunks IS '知识库分块表，与 Milvus kb_vectors 通过 vector_id 1:1 关联';

-- ============================================================
-- 8.1 知识库资产表（V5 新增，结构化预览载体）
-- ============================================================
CREATE TABLE kb_doc_assets (
    id BIGSERIAL PRIMARY KEY,
    doc_id UUID NOT NULL REFERENCES kb_documents(id) ON DELETE CASCADE,
    asset_type VARCHAR(10) NOT NULL CHECK (asset_type IN ('image','table')),
    page INT NOT NULL DEFAULT 0,
    storage_path VARCHAR(500) NOT NULL,
    ocr_text TEXT,
    mime_type VARCHAR(100),
    content_json TEXT,
    create_time TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_kb_doc_assets_doc ON kb_doc_assets(doc_id);
CREATE INDEX idx_kb_doc_assets_doc_type ON kb_doc_assets(doc_id, asset_type);
COMMENT ON TABLE kb_doc_assets IS '知识库文档内嵌资产表（图片/表格，结构化预览载体）';
COMMENT ON COLUMN kb_doc_assets.content_json IS '表格行列结构 JSON（{"headers","rows"}），gr.Dataframe 渲染源';
COMMENT ON COLUMN kb_doc_assets.storage_path IS '资产本地相对路径（KB_ASSETS_DIR 下 doc_id/ 目录），与 Gradio 共享 volume 读取';
COMMENT ON COLUMN kb_doc_assets.ocr_text IS '图片 OCR 识别文本（图片资产可空）';

-- ============================================================
-- 9. 敏感词词库表
-- ============================================================
CREATE TABLE sensitive_words (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    word VARCHAR(100) NOT NULL UNIQUE,
    category VARCHAR(20) NOT NULL CHECK (category IN ('threat','abuse','induce')),
    severity VARCHAR(10) NOT NULL CHECK (severity IN ('high','medium','low')),
    status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled')),
    description VARCHAR(255),
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_sensitive_words_category ON sensitive_words(category);
CREATE INDEX idx_sensitive_words_severity ON sensitive_words(severity);
COMMENT ON TABLE sensitive_words IS '敏感词词库，QC 与 AI 输出拦截共用，命中即 B0010 拦截';

-- ============================================================
-- 10. 质检规则表
-- ============================================================
CREATE TABLE qc_rules (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    rule_type VARCHAR(30) NOT NULL CHECK (rule_type IN ('keyword','regex','semantic','duration','silence')),
    pattern TEXT NOT NULL,
    severity VARCHAR(10) NOT NULL CHECK (severity IN ('high','medium','low')),
    score_deduct INT NOT NULL DEFAULT 10 CHECK (score_deduct BETWEEN 0 AND 100),
    status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled')),
    description VARCHAR(255),
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))
);
CREATE INDEX idx_qc_rules_rule_type ON qc_rules(rule_type);
CREATE INDEX idx_qc_rules_severity ON qc_rules(severity);
COMMENT ON TABLE qc_rules IS '质检规则表，扣分项可配置，默认 10-30';

-- ============================================================
-- 11. 分案策略表

    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))

CREATE INDEX idx_assignment_strategies_status ON assignment_strategies(status);

-- ============================================================
-- 12. 外呼策略表
-- ============================================================
CREATE TABLE call_strategies (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),

    version INT DEFAULT 1,
    status VARCHAR(20) NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','active','archived')),
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))

CREATE INDEX idx_call_strategies_status ON call_strategies(status);
CREATE INDEX idx_call_strategies_name ON call_strategies(name);
COMMENT ON TABLE call_strategies IS '外呼策略表，管"如何呼"；assignment_strategies 管"分给谁"';
COMMENT ON COLUMN call_strategies.rules IS '含外呼时段/重试/限流/熔断阈值，默认值见 step3/01 第十节';

-- ============================================================
-- 13. 策略版本表

CREATE TABLE strategy_versions (

    version INT NOT NULL,

    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1')),
    UNIQUE(strategy_type, version)
);
CREATE INDEX idx_strategy_versions_strategy_type ON strategy_versions(strategy_type);
CREATE INDEX idx_strategy_versions_status ON strategy_versions(status);
COMMENT ON TABLE strategy_versions IS '策略版本表，统一管理各类策略版本与审批，支持回滚';

-- ============================================================
-- 14. 用户特征宽表
-- ============================================================
CREATE TABLE features_user (
    case_id UUID PRIMARY KEY REFERENCES cases(id) ON DELETE CASCADE,
    willingness_score INT CHECK (willingness_score BETWEEN 0 AND 100),
    ability_score INT CHECK (ability_score BETWEEN 0 AND 100),
    complaint_risk_score INT CHECK (complaint_risk_score BETWEEN 0 AND 100),
    overall_risk_level VARCHAR(10) CHECK (overall_risk_level IN ('low','medium','high')),

    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
CREATE INDEX idx_features_user_overall_risk_level ON features_user(overall_risk_level);
COMMENT ON TABLE features_user IS '用户特征宽表，data-platform 离线计算产出，权重 意愿0.4/能力0.3/投诉0.3';

-- 15. 投诉工单表

    suggestion TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','investigating','resolved','closed')),

    update_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_delete CHAR(1) NOT NULL DEFAULT '0' CHECK (is_delete IN ('0','1'))

    scripts JSONB DEFAULT '[]'::jsonb,
    create_time TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

CREATE INDEX idx_review_cases_category ON review_cases(category);

-- ============================================================
-- 17. LLM 调用审计表（append-only，宪法强制）
-- ============================================================
CREATE TABLE llm_call_logs (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    trace_id VARCHAR(100) NOT NULL,
    session_id VARCHAR(100),
    provider VARCHAR(50) NOT NULL,
    model VARCHAR(50),
    prompt TEXT NOT NULL,
    response TEXT,
    token_usage JSONB,
    latency_ms INT,
```

## 六、Alembic 迁移约束

- 所有表结构变更必须经 `alembic revision --autogenerate` 生成迁移脚本，Code Owner 双人评审后 `alembic upgrade`，禁手动 DDL；
- 迁移脚本含 `upgrade()` 与 `downgrade()`，必须可回滚；数据迁移与结构迁移分脚本提交；
- 生产迁移窗口 02:00–05:00，大表加列分两步（先加可空列 → 回填 → 改非空）；
- 验收：`alembic upgrade head` 零错误；pytest 覆盖率≥85%；ORM 与 DDL 反射逐一对应；Pydantic Literal 与 CHECK IN 双向对齐脚本通过；Milvus kb_vectors 可写入检索 768 维；三张强制 DWS 表 ETL 可产出。
