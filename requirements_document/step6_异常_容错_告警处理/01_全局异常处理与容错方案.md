## 一、异常分类矩阵

### 1.1 六类异常

| 类别 | 异常类型 | 触发场景 | 错误码域 | HTTP 状态码 | 日志级别 |
|---|---|---|---|---|---|
| DB | 数据库异常 | 连接超时、死锁、约束冲突、唯一键冲突 | B0007 | 500/503 | ERROR |
| Network | 网络异常 | HTTP 调用超时、连接拒绝、DNS 解析失败 | B0008 | 502/504 | ERROR |
| LLM | 大模型调用异常 | 超时、返回非法 JSON、Schema 校验失败、置信度不足 | A1010/A1013 | 200 | WARNING |
| Timeout | 超时异常 | 外部调用 5s 超时、ASR 静默 10s、对话 15 轮上限 | A1005~A1007 | 200 | WARNING |
| Business | 业务校验异常 | 非工作时段外呼、重试超限、并发超限、参数校验失败 | A1xxx~A7xxx | 200/422 | INFO |
| Auth | 权限异常 | 未认证、无权限、token 过期、数据隔离越权 | B0002/B0003 | 401/403 | WARNING |

### 1.2 业务异常 vs 系统异常

| 维度 | 业务异常 | 系统异常 |
|---|---|---|
| 本质 | 业务规则不满足（如非工作时段） | 基础设施/外部依赖故障（如 DB 宕机） |
| 错误码 | A 系列（A1xxx~A7xxx） | B 系列（B0001~B0010） |
| HTTP 状态码 | 200（统一封装） | 500/502/503/504 |
| 日志级别 | INFO/WARNING | ERROR |
| 告警 | 不告警或低级告警 | 必须告警 |
| 用户提示 | 友好业务提示 | "系统繁忙，请稍后重试" |
| 重试 | 不重试（业务规则） | 有限重试 + 降级 |

## 二、处理原则

| # | 原则 | 执行标准 | openspec 对齐 |
|---|---|---|---|
| 1 | 全局捕获 | 所有异常经 `common/errors/handlers.py` 统一捕获，禁止接口原生 500 报错、禁止堆栈对外暴露 | 强制1 |
| 2 | 分类捕获 | `try-except` 必须捕获具体异常（如 `HTTPException`、`sqlalchemy.exc.DBAPIError`），禁止裸 `except:` | 强制2 |
| 3 | 有限重试 | 核心操作有限次数重试（3 次指数退避 1s/2s/4s），重试失败自动降级，禁止无限重试 | 强制3 |
| 4 | 高危告警 | 合规拦截、LLM 批量失败、异常访问、SQL 高危操作、接口报错暴涨触发告警 | 强制4 |
| 5 | 友好提示 | 对外错误文案友好、简洁、无技术术语、无路径泄露、无堆栈信息 | 强制5 |
| 6 | 完整日志 | 所有异常必须日志完整记录：入参、报错堆栈、请求 ID、会话 ID、时间戳、trace_id | 强制6 |
| 7 | 错误码基线 | 以本文件 84 条全集为唯一基线（含 DD 扩展码），新增须经评审收录 | 强制7 |

## 四、重试与超时参数

### 4.1 通用外部调用

| 参数 | 值 | 说明 |
|---|---|---|
| 超时 | 5s | 适用于 HTTP 调用、LLM 调用 |
| 重试次数 | 3 次 | 适用于 HTTP 调用、LLM 调用 |
| 退避策略 | 指数退避 1s / 2s / 4s | 逐步增加等待时间 |
| 重试条件 | 超时、网络异常、JSON 解析失败、Schema 校验失败 | 业务异常不重试 |
| 重试耗尽 | 触发降级 | 不让调用方卡死 |

### 4.2 各服务特化参数

| 服务 | 场景 | 超时 | 重试 | 降级动作 |
|---|---|---|---|---|
| call-service | LLM 调用 | 5s | 3 次 | RuleBasedScriptEngine 兜底 |
| call-service | ASR | 3s | 3 次 | 播报"没听清"，累计 5 次结束 |
| call-service | TTS | 3s | 3 次 | 播放预设提示音 + 结束 |
| call-service | CCC 外呼 | 10s | 3 次 | 标记待重试，计入下轮调度 |
| call-service | RAG 检索 | 3s | 1 次 | 返回空 + FAQ 兜底 |
| call-service | QC 旁路 | 3s | 0 次 | 降级为事后质检（非阻断） |
| qc-service | LLM 审查 | 5s | 3 次 | 降级为规则引擎审查 |
| rag-service | Embedding | 5s | 3 次 | 返回空 + 跳过向量化 |
| complaint-service | LLM 判责 | 10s | 3 次 | 降级为规则兜底判责 |
| review-service | LLM 分类 | 10s | 3 次 | 降级为规则分类 |
| data-platform | ETL 同步 | 30s | 3 次 | 告警 + 数据不丢失 |
| data-platform | 策略回流 | 10s | 3 次 | 回滚 + 保持上一版本 |

## 五、熔断配置

### 5.1 LLM 熔断（pybreaker）

| 参数 | 值 | 说明 |
|---|---|---|
| 触发条件 | 连续 3 次失败 或 P95 > 800ms | 任一满足即熔断 |
| 熔断窗口 | 窗口期内停止 LLM 调用 | 走 RuleBasedScriptEngine 固定兜底 |
| 恢复探测 | 60s 后半开探测 | 恢复后重试 LLM 调用 |
| Redis 标识 | `{service}:llm_degraded` = "1" | 见 step4/03 |
| 适用服务 | complaint-service / review-service | 两服务各自独立熔断 |

### 5.2 ASR 熔断

| 参数 | 值 | 说明 |
|---|---|---|
| 触发条件 | 连续 3 次置信度 < 0.5 | ASR 质量差 |
| 降级动作 | 播报"没听清，请您再说一遍" | — |
| 结束条件 | 累计 5 次 | 结束通话 |

### 5.3 服务间调用熔断

| 调用链 | 熔断条件 | 降级动作 |
|---|---|---|
| call-service → rag-service | RAG 连续 3 次超时 | 返回空 + FAQ 兜底 |
| call-service → qc-service | QC 旁路连续 3 次超时 | 降级为事后质检（非阻断） |
| case-service → data-platform | DP 连续 3 次超时 | 降级为缓存策略（A7001） |
| complaint-service → rag-service | 知识库连续 3 次超时 | 降级为规则兜底判责 |

| call-service | QC 旁路超时 | 降级为事后质检（非阻断） | A2001 |
| qc-service | LLM 审查失败 | 降级为规则引擎审查 | A2003 |
| rag-service | Embedding 失败 | 跳过向量化 + 告警 | A3003 |

| review-service | LLM 分类失败 | 降级为规则分类 | A6003 |

### 6.2 降级优先级

```
正常流程
  → LLM 失败/超时 → 重试 3 次
    → 重试成功 → 正常继续
    → 重试耗尽 → 熔断 → RuleBasedScriptEngine 兜底
  → RAG 无匹配 → FAQ 标准答案兜底
  → ASR 不可用 → 兜底话术 + 累计 5 次结束
  → TTS 不可用 → 预设提示音 + 结束
  → QC 旁路超时 → 非阻断，降级事后质检
  → DP 不可用 → 缓存策略降级
  → 合规拦截 → 兜底话术 + B0010 + 告警
```

## 七、全局异常处理器实现

### 7.1 实现位置

`common/errors/handlers.py`，FastAPI 全局异常中间件。

### 7.2 处理流程

```
请求进入
  → 业务层 try-except 捕获具体异常
    → 业务异常 (BizException)
      → 封装 {code: A1xxx, message: 友好提示, data: null, trace_id}
      → 日志 INFO/WARNING
      → 返回 200
    → 系统异常 (SysException)
      → 封装 {code: B0xxx, message: "系统繁忙", data: null, trace_id}
      → 日志 ERROR + 告警
      → 返回 5xx
    → 未捕获异常 (Exception)
      → 全局兜底捕获
      → 封装 {code: B0009, message: "系统繁忙，请稍后重试", data: null, trace_id}
      → 日志 ERROR + 告警
      → 返回 500
```

### 7.3 代码结构

```python
# common/errors/codes.py
class ErrorCode:
    # A 系列 - 业务异常
    A1001 = "A1001"  # 非工作时段外呼
    A1010 = "A1010"  # LLM 置信度不足转人工
    A1013 = "A1013"  # 语音链路异常
    # ... 全量 84 条
    B0010 = "B0010"  # 合规拦截

# common/errors/exceptions.py
class BizException(Exception):
    """业务异常，返回 A 系列码"""
    def __init__(self, code: str, message: str):
        self.code = code
        self.message = message

class SysException(Exception):
    """系统异常，返回 B 系列码"""
    def __init__(self, code: str, message: str = "系统繁忙"):
        self.code = code
        self.message = message

# common/errors/handlers.py
async def global_exception_handler(request, exc):
    """全局异常处理器，统一封装响应包"""
    trace_id = get_trace_id()
    if isinstance(exc, BizException):
        log.warning(...)
        return JSONResponse(200, {"code": exc.code, "message": exc.message, "data": None, "trace_id": trace_id})
    elif isinstance(exc, SysException):
        log.error(...)
        send_alert(...)
        return JSONResponse(500, {"code": exc.code, "message": "系统繁忙", "data": None, "trace_id": trace_id})
    else:
        log.error(...)
        send_alert(...)
        return JSONResponse(500, {"code": "B0009", "message": "系统繁忙，请稍后重试", "data": None, "trace_id": trace_id})
```

## 八、对外错误文案规范

### 8.1 文案原则

| 原则 | 说明 |
|---|---|
| 友好简洁 | 面向用户/运营，无技术术语 |
| 无路径泄露 | 禁止暴露文件路径、类名、方法名 |
| 无堆栈信息 | 禁止返回异常堆栈给前端 |
| 无数据库信息 | 禁止暴露表名、字段名、SQL 语句 |
| 统一话术 | 系统异常统一为"系统繁忙，请稍后重试" |

### 8.2 文案对照表

| 错误码 | 对外文案 | 对内日志 |
|---|---|---|
| A1001 | "当前不在外呼时段内" | 非工作时段外呼拦截 |
| A1004 | "该客户多次未接通，已标记失联" | 重试超限 |
| A1005 | "未能听清您的回复，请您再说一遍" | ASR 连续失败 |
| A1007 | "对话已达上限，正在为您转接专属顾问" | 对话轮次超限 |
| A1010 | "为了更好地为您服务，正在为您转接专属顾问" | LLM 置信度不足 |
| A1013 | "语音服务暂时不可用，请稍后重试" | 语音链路异常 |
| B0007 | "系统繁忙，请稍后重试" | DB 连接超时: {detail} |

| B0010 | "为了保障服务质量，正在为您转接专属顾问" | 合规拦截: {hit_detail} |

## 九、AI 开发硬性指令

> openspec/specs/06 AI 开发硬性指令：所有新增功能必须配套异常捕获与容错兜底，无容错逻辑视为代码缺陷。

| 检查项 | 标准 |
|---|---|
| 异常捕获 | 所有外部调用（LLM/ASR/TTS/CCC/Redis/Milvus/HTTP）必须有 try-except |
| 重试机制 | 核心调用必须有 `@retry` 装饰器（3 次指数退避） |
| 降级兜底 | 重试耗尽必须有降级动作（兜底话术/规则引擎/缓存） |
| 错误码 | 必须使用本文件 84 条中的错误码 |
| 日志记录 | 必须记录入参摘要 + 异常类型 + 堆栈 + trace_id |
| 告警触发 | 系统异常必须触发告警 |
| CI 门禁 | 代码审查发现无容错逻辑的直接驳回 |
