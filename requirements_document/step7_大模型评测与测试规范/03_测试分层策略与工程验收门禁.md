## 一、四层测试金字塔

```
                    ┌──────────┐
                    │   E2E    │  ← 端到端测试（少量，覆盖关键业务路径）
                  ┌─┴──────────┴─┐
                  │  Integration │  ← 集成测试（中量，跨模块/跨服务）
                ┌─┴──────────────┴─┐
                │      Smoke       │  ← 冒烟测试（脚本目录 7 套；CI 按 §7.2 里程碑裁剪）
              ┌─┴──────────────────┴─┐
              │       Unit           │  ← 单元测试（大量，函数/类级）
```

## 三、CI 流水线

### 3.1 PR 合并门禁（DEVELOPMENT_CONTRACT 第 6 节）

所有 PR 必须通过以下三项门禁，零错误方可合并：

```
PR 提交
  → ruff check .           （行宽 120，零错误）
  → bandit -r .            （安全扫描，零高危）
  → mypy                   （类型检查，关键模块通过）
  → pytest --cov --cov-report=term-missing
    → 覆盖率 ≥85%
    → 全部测试用例通过
  → LLM 回归测试集           （拦截率 100%）
  → 幻觉测试集               （0 编造）
  → 降级熔断测试             （全部正确降级）
  → 一致性测试               （枚举一致率 ≥90% + 人工复核）
    → 全部通过 → 允许合并
    → 任一未通过 → 阻断合并
```

### 3.2 静态扫描规则

| 工具 | 规则 | 阻断条件 |
|---|---|---|
| ruff | 行宽 120 | 任一 error |
| bandit | 安全扫描 | 任一 high severity |
| mypy | 类型检查 | 关键模块（common/）任一 error |

### 3.3 PR 模板自检

PR 须包含以下自检勾选（DEVELOPMENT_CONTRACT 第 6 节）：

- [ ] 无 `time.sleep()`
- [ ] 无裸 `except:`
- [ ] 无硬编码密钥
- [ ] 敏感信息已脱敏
- [ ] 新增功能配套异常捕获与容错兜底
- [ ] 新增 AI 功能配套 LLM 回归用例
- [ ] 测试覆盖率 ≥85%

## 四、Shell 冒烟脚本（7 服务独立）

### 4.1 设计原则

- 每服务一个独立 Shell 脚本，互不依赖；
- 脚本位于 `scripts/smoke/`，命名 `smoke_<service>.sh`；
- 脚本先启动服务容器（或假定已启动），再逐接口验证；
- 输出统一格式：`[PASS]` / `[FAIL]` + 描述；
- 任一 FAIL 即脚本退出码 1。

### 4.2 冒烟脚本清单

| 脚本 | 服务 | 启用里程碑 | 验证项（CI 阻断） |
|---|---|---|---|
| `smoke_data_platform.sh` | data-platform (8001) | M1 起 | **M1 阻断仅** `GET /health` + `GET /api/v1/data/sessions/{session_id}/qc-source` + `GET /api/v1/data/sessions:pending-qc`（第 20 条已上收）。**不要**把 ETL 触发 / 日报查询当 M1 阻断（无 DD 禁止越权） |
| `smoke_rag_service.sh` | rag-service (8002) | M1 起 | `/health`、知识库文档 CRUD、向量检索 |
| `smoke_qc_service.sh` | qc-service (8003) | M1 起 | `/health`、质检规则查询、敏感词拉取。独立可测断言 **不在本脚本复制**：CI 必跑集见 **DD-02 §8.2 断言 1～28** |
| `smoke_call_service.sh` | call-service (8004) | M2 起 | 无 DD 期间允许 `/health` 占位冒烟；批次创建/模拟器随实现加深 |
| `smoke_case_service.sh` | case-service (8005) | M2 起 | 无 DD 期间允许 `/health` 占位冒烟 |
| `smoke_complaint_service.sh` | complaint-service (8006) | M3 起 | `/health`、投诉工单创建、判责查询（**API** 主链路，允许 Mock MCP）。**不含人审前端**（前端属 M3.5） |
| `smoke_review_service.sh` | review-service (8007) | **M4 才执行** | `/health`、复盘分类、报告查询。可留在清单，M1～M3 **不跑、不卡** |

> 与覆盖矩阵同构：review 无目录属 M4；call/case 无 DD，M2 起才进阻断集。**禁止**要求 M1 先有 review/call 深做。

### 4.3 脚本模板

```bash
#!/usr/bin/env bash
# scripts/smoke/smoke_<service>.sh
set -euo pipefail

SERVICE="<service-name>"
PORT="<port>"
BASE="http://localhost:${PORT}"
PASS=0; FAIL=0

check() {
  local name="$1"; local url="$2"; local expect="$3"
  local resp
  resp=$(curl -s -o /dev/null -w "%{http_code}" "${url}" 2>/dev/null || echo "000")
  if [[ "${resp}" == "${expect}" ]]; then
    echo "[PASS] ${name}"
    ((PASS++))
  else
    echo "[FAIL] ${name} (expected ${expect}, got ${resp})"
    ((FAIL++))
  fi
}

echo "=== Smoke Test: ${SERVICE} ==="
check "health"     "${BASE}/health"                 "200"
check "list_items" "${BASE}/api/v1/<resource>?page=1&page_size=1" "200"
# ... 添加更多接口验证

echo ""
echo "=== Result: ${PASS} passed, ${FAIL} failed ==="
[[ ${FAIL} -eq 0 ]] && exit 0 || exit 1
```

## 六、外部服务 Mock 策略

### 6.1 Mock 原则

> DEVELOPMENT_CONTRACT 第 7 节：外部服务（大模型/ASR/TTS/呼叫中心/Milvus）必须 Mock，脱网可跑全测试。

| 外部服务 | Mock 工具 | Mock 策略 |

| Redis | testcontainers 或 fakeredis | 集成测试用真实 Redis，单元测试 fakeredis |
