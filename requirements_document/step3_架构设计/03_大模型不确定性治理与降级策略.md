## 一、不确定性治理

1. LLM 输出必须依赖数据库/知识库检索结果，禁止凭空生成金额、时间、政策、记录、结论；
2. RAG 检索 score<0.6 判定无匹配，直接兜底回答，禁止强行回答；**score 口径 = 混合检索（Milvus IP 向量分 + ES BM25 稀疏分）经 bge-reranker 精排后的最终融合分数**（阈值语义与字段定义见 step4/02 §四.1，配置常量 RAG_SCORE_THRESHOLD 见 step5/01 §八）；
3. LLM 输出 confidence<0.7 禁止直接回复用户，触发兜底或转人工；
4. 意图识别 confidence<0.6 记 uncertain 不阻断流程，但落记录；
5. 关键业务字段（金额、政策、逾期天数）开启结构化输出 + 字段强校验，校验不过丢弃重生成。
6. LLM 输出涉及法规/政策/金额/逾期天数等结论性内容，**必须附 RAG source_id + 原文片段引用**（source_id = kb_chunks.doc_id / kb_documents.id，拼装口径见 step4/02 §四.3）；无 source_id 支撑的法规/结论视为幻觉、禁止放行（由后置 L4 法规来源校验拦截，见 step5/04 §3.2）。

## 二、降级总原则与兜底分级

LLM 超时、报错、检索为空，全部走业务兜底，禁止抛异常给终端客户。分级如下：

| 层级 | 触发 | 兜底动作 |
|---|---|---|
| L1 LLM 调用失败 | 超时/熔断/报错 | 返回预设兜底话术（RuleBasedScriptEngine 本地决策树） |
| L2 知识库检索无果 | score<0.6 或为空 | 使用标准 FAQ 兜底，不自由作答 |
| L3 合规拦截触发 | 前置/后置校验不通过 | 返回合规兜底话术，记告警，违规内容不向下游传递 |

兜底话术统一在 rag-service 标准答案库维护，禁止硬编码在业务代码（详见 step1/03 兜底话术表）。

## 三、容错与降级矩阵

| 依赖 | 熔断/失败阈值 | 降级方案 | 依据 |
|---|---|---|---|
| 大模型 API | 连续 3 次失败；P95 按模型分层 | 外呼/质检/复盘及 qwen-plus/turbo：P95>800ms 切 RuleBasedScriptEngine。投诉 **deepseek-r1** 判责：P95>15s，按 DD-05 **§8.5** 降到 qwen-plus（禁止对投诉判责一刀切 800ms） | openspec 04/06；DD-05 §8.5 |
| ASR | 连续 3 次置信度<0.5 | 播报"抱歉没听清，请您再说一遍"；累计 5 次结束通话 | step1/01 |
| TTS | 合成失败 | 播放预设兜底提示音，结束通话 | step1/01 |
| RAG 检索 | 服务超时/报错 | 降级为静态标准话术库，记录降级日志 | openspec 04 |
| RAG 置信度 | score<0.6 | 返回空 + 标记"知识库无匹配"，调用方走兜底 | step1/01 |
| LLM 置信度 | confidence<0.7 | 禁止直接回复，触发转人工 | step1/01 |
| 呼叫中心 | 接口超时/报错 | 任务标记待重试，计入下一轮调度 | step1/01 |
| 质检服务 | 通话未结束或 ODS 全文未齐 | 不开工；WAIT_TEXT 重试（A2003）。qc **不在**通话链路，无「3s 旁路超时」 | DD-02 V1.5 |
| qc 离线 LLM 语义复核 | 5s 超时 / HTTP 500 / 非法 JSON / Schema 失败，连续 3 次 → 熔断 | 跳过 LLM 复核，仅 AC + 规则打分仍出分；兜底返回空 LLMHit 列表、qc_status 仍 DONE（不阻塞；qc 为离线，无通话实时「兜底话术」语义）；恢复：60s 后半开探测成功清除熔断；告警：A2011 → system.alert.raised | DD-02 §14 V1.5 |
| qc 词库(current.dict) | 拉取失败 | 保持旧 AC 自动机继续检测，重试成功后热刷新，不中断离线质检 | DD-02 §14 V1.5 |
| 数据中台同步 | 失败 | 自动重试 3 次，仍失败告警，数据不丢失 | openspec 06 |
| 策略回流 | 失败 | 自动回滚，保障业务规则稳定 | openspec 06 |
| 对话轮次 | 达 13 轮 | AI 主动引导结束；达 15 轮强制转人工 | step1/01 |
| 话术重复 | 3 轮内完全相同话术 | 立即抛异常转人工 | step1/01 |
| 并发呼叫 | >50 路 | asyncio.Semaphore(50) + 令牌桶，超额排队 | step1/01 |

> **温度分层与"话术重复转人工"的兼容性（批次2 厘清）**：生产对话生成默认 temperature=0.3、可配置 0.1~0.5、seed 不固定（step5/03 §6.2），已显著降低 LLM 逐字重复输出概率；"3 轮内完全相同话术立即转人工"属合规安全网，防止异常态卡死通话，与温度参数解耦、始终生效。评测/回归分支固定 temperature=0.1 + seed=42（step7/01 v1.1）仅用于离线一致性评测，不产生在线话术，不受本规则约束。

## 四、熔断与重试参数

- 服务间同步调用（管理面/CRUD）：**5s** 超时 + 3 次指数退避（1s/2s/4s）；
- LLM **全局默认**（外呼/质检/通用 HTTP）：**5s** + 3 次、退避 1s/2s/4s。**禁止**把全局默认改成 10s；15s 只是 deepseek-r1 的 P95 熔断阈值（见 DD-05 §8.5），不是超时；
- LLM 熔断：窗口期内连续 3 次失败触发熔断；P95 分层见上表与 DD-05 §8.5；窗口期内停止调用大模型、走固定兜底；
- ASR 连续 3 次置信度<0.5 走兜底，累计 5 次结束通话；用户静默 10 秒引导、20 秒结束；
- 数据中台同步失败自动重试 3 次，仍失败告警，数据不丢失；
- 策略回流失败自动回滚，保障业务规则稳定。

### 4.1 按服务 LLM 超时覆盖表（与 step6/01 §4.2 逐行一致）

全局默认 5s 不变。下列为已有覆盖例外，数字不得改。

| 服务 | 场景 | 超时 | 重试 | 降级动作 |
|---|---|---|---|---|
| call-service | LLM 调用 | 5s | 3 次 | RuleBasedScriptEngine 兜底 |
| call-service | ASR | 3s | 3 次 | 播报"没听清"，累计 5 次结束 |
| call-service | TTS | 3s | 3 次 | 播放预设提示音 + 结束 |
| call-service | CCC 外呼 | 10s | 3 次 | 标记待重试，计入下轮调度 |
| call-service | RAG 检索 | 3s | 1 次（豁免） | 返回空 + FAQ 兜底 |
| qc-service | LLM 审查 | 5s | 3 次 | 降级为规则引擎审查 |
| rag-service | Embedding | 5s | 3 次 | 入库中止：status=failed + A3003（禁止跳过向量化仍入库） |
| complaint-service | LLM 判责 | 10s | 3 次 | 降级为规则兜底判责 |
| review-service | LLM 分类 | 10s | 3 次 | 降级为规则分类 |
| data-platform | ETL 同步 | 30s | 3 次 | 告警 + 数据不丢失 |
| data-platform | 策略回流 | 10s | 3 次 | 回滚 + 保持上一版本 |

> 豁免说明与 step6/01 §4.2 相同：call-service RAG 检索重试 1 次为实时链路有意设计。**无 QC 旁路**。

## 五、通话轮次与并发约束

- 单通话最大 15 轮，第 13 轮触发关键要素判断分支、AI 主动引导结束；
- 3 轮内完全相同话术立即抛异常转人工（与温度参数解耦、始终生效，兼容性口径见 §三 矩阵表下注）；
- 并发上限 50 路（asyncio.Semaphore(50) + 令牌桶），超额排队；
- 外呼时段 08:00–21:00，非时段入口拦截返回 A1001。

## 六、监控告警

高危事件必须告警记录（对齐 openspec/specs/06 强制4）：

- LLM 批量失败、高频超时、熔断触发；
- 合规拦截触发（前置/后置）；
- 异常访问、SQL 高危操作；
- 接口报错暴涨、并发触达上限；
- 数据中台同步/策略回流失败。

所有超时、熔断、降级事件完整埋点日志（入参、报错堆栈、请求 ID、会话 ID、时间戳、trace_id），送入数据中台并支持告警与问题复盘。
