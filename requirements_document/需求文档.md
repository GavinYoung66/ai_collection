## 1 项目概述

### 1.1 项目背景

贷后电话催收是金融信贷业务闭环的核心环节，面向信用卡、消费贷、小微贷等逾期用户开展合规触达、还款提醒、纠纷协商与回款跟进。传统催收模式高度依赖人力，存在四重核心瓶颈：

1.  **成本瓶颈**：岗位强度高、流失率大，新人培养周期长，海量早期逾期案件占用大量人力，产能扩张与成本线性绑定。
2.  **合规瓶颈**：传统系统仅能存储录音，质检抽样覆盖率不足5%；AI 出口缺少护栏、通话结束后又无全量质检，违规发现滞后、补救代价高。
3.  **质量瓶颈**：客户意向判断、话术尺度全依赖个人经验，不同坐席作业效果差异大，业务质量不稳定。
4.  **迭代瓶颈**：通话数据、优质话术、失败经验均为非结构化信息，无法批量沉淀与复用，策略迭代依赖人工经验传承。

伴随大模型、语音AI、RAG知识库、数据中台技术成熟，可通过认知能力赋能传统催收流程。本项目基于一线催收业务实操经验，搭建七大AI能力子系统，构建“传统业务流程+AI认知能力+数据闭环迭代”的人智协同催收体系，实现降本、增效、合规、智能化迭代的核心目标。

### 1.2 业务目标

1.  **规模化触达**：账龄 M0/M1（`account_stage`）早期轻度逾期案件实现AI外呼100%覆盖，替代人工重复性提醒工作。
2.  **全量合规管控**：通话中由外呼 Guardrails 拦截违规出口；通话结束后 100% 离线全量质检，高危事后告警主管。
3.  **作业标准化**：统一话术标准与案件分层规则，降低人工经验差异带来的业务波动。
4.  **数据闭环迭代**：全链路通话、标签、回款数据可追溯、可分析，自动沉淀经验并反向优化业务策略。
5.  **人效优化**：通过智能分案实现人机分流，将资深人力聚焦于高价值疑难案件。

### 1.3 项目范围

#### 1.3.1 包含范围（MVP版本）

- 传统业务底座对接：案件信息、呼叫中心、工单基础能力复用现有系统。
- 七大AI子系统核心能力：AI外呼对话、离线录音质检、RAG全局知识库、智能案件分案、投诉异议研判、智能复盘培训、催收数据中台，保障催收全流程核心链路跑通。
- 基础权限管理、数据脱敏、操作审计等安全合规能力。
- 核心数据统计看板与结构化报表导出。

> **可开发 vs 仅规划（对齐覆盖矩阵 step1/04，不新写功能）**：有独立 DD 的 rag / qc / complaint = **可开发**；call / case / review / 中台其余 = **仅规划，无 DD 禁止开工**（中台例外仅 `qc-source` / `pending-qc`）。FR-TR-004 模拟对打 = **里程碑 M5+ / 非 MVP**，不得当里程碑 M1～M4 验收。Text2SQL = **已排除**（保持里程碑 M5 之后）。

#### 1.3.2 MVP版本不包含范围

- 多租户隔离与多机构管理能力；
- 大模型在线微调、模型训练平台化能力；
- 移动端坐席作业端与小程序应用；
- 面向第三方系统的开放API接口；
- 高度自定义可视化报表配置能力；
- AI模拟对打培训（FR-TR-004，**里程碑 M5+ / 非 MVP**）、坐席能力精细化画像等进阶培训功能；
- Text2SQL（**已排除**，保持里程碑 M5 之后；账单查询走 RAG + 结构化接口）。

### 1.4 全局假设与约束

1.  **业务假设**：系统对接现有呼叫中心与传统催收业务系统，可获取案件基础数据、通话录音与工单数据。
2.  **合规约束**：严格遵循《个人信息保护法》《催收自律公约》，禁止暴力催收、骚扰第三方、违规承诺等行为。
3.  **技术约束**：所有AI能力以微服务API形式接入现有系统，不推翻原有业务架构，支持灰度迭代。
4.  **数据约束**：所有通话录音、客户敏感信息必须按监管要求留存，操作全程留痕可审计。

## 2 整体业务架构

### 2.1 核心设计原则

- **权责分离**：传统系统负责流程调度、数据落库、业务执行；AI仅负责认知判断、打分、建议输出，隔离大模型幻觉的业务风险。
- **链路分离**：实时交互链路低延迟优先，不经过数据中台；离线计算链路统一走数据中台，保障口径一致与性能稳定。
- **模块解耦**：七大子系统独立部署、独立迭代，通过标准化接口交互，单个模块故障不影响全局业务。

### 2.2 系统总体分层架构

系统采用四层企业级架构，自上而下分别为：

1.  **传统业务底座层**：案件管理、工单流转、呼叫中心、权限管理、回款闭环、业务数据库，保障基础业务稳定运行。
2.  **AI实时能力层**：AI外呼对话、实时意图识别、Guardrails 护栏，支撑通话全流程低延迟智能交互与事中拦截（质检不在本层）。
3.  **AI智能业务中枢层**：RAG全局知识大脑、离线录音质检、智能分案、投诉研判、复盘培训，实现业务智能化决策与团队赋能。
4.  **数据中台底座层**：数据汇聚、清洗、宽表融合、特征工程、样本管理、离线策略迭代，实现全链路数据自闭环。

### 2.3 七大子系统职责边界

| 子系统名称               | 核心定位         | 核心产出                               |
| :----------------------- | :--------------- | :------------------------------------- |
| AI智能外呼对话系统       | 对外实时交互入口 | 自动化外呼、AI对话、结构化通话结果     |
| AI录音质检系统           | 事后合规审计守门员 | 离线违规检测、合规打分、违规台账、事后告警 |
| RAG多模态全局知识库系统  | 全项目AI知识大脑 | 合规话术、法规依据、优质案例检索结果   |
| AI智能案件分层分案系统   | 业务智能调度中枢 | 风险打分、案件分层、人机分流、智能派单 |
| AI投诉异议智能研判系统   | 客诉风险兜底模块 | 投诉取证、责任判责、整改方案生成       |
| AI智能复盘与人才培训系统 | 团队能力迭代中枢 | 案例沉淀、话术提炼、复盘报告           |
| AI催收专属数据中台系统   | 全量数据底座     | 统一数据口径、特征计算、策略回流       |

> **命名口径注（V1.2）**：质检正式名为 **AI录音质检系统**（`qc-service` / 8003），**仅离线全量、无实时旁路**。其余子系统正式名称、服务名与端口以 [step1_项目总览/01_项目概述与背景.md](step1_项目总览/01_项目概述与背景.md) 为准。

### 2.4 全链路业务流程

1.  **事前阶段**：数据中台同步清洗全量逾期案件，计算用户风险特征与画像；智能分案系统完成案件分层与人机分流；RAG知识库同步最新合规话术与规则。
2.  **通话实时阶段**：账龄 M0/M1（`account_stage`）轻量案件由AI外呼自动触达，账龄 M2/M3 疑难案件由人工坐席处理；全程ASR实时转写，RAG赋能话术，Guardrails 做出口拦截。质检系统**不介入**通话。
3.  **通话结束近实时阶段**：录音与 ASR 全文落库后，qc-service 启动离线全量质检并事后告警主管；同时解析意向/情绪/风险标签，生成摘要回填工单，并执行动态二次分案。
4.  **售后兜底阶段**：产生用户投诉时，AI自动回溯全量通话记录，完成证据提取、责任判责与解决方案生成。
5.  **离线迭代阶段**：全量通话、标签、回款数据同步至数据中台；AI自动复盘优劣案例、迭代话术与拨打策略，优化后的策略回写业务系统，进入下一轮业务循环。

### 2.5 全链路数据流转规则

1.  **数据入湖**：传统业务库、呼叫中心录音、工单数据、AI模块输出标签通过ETL/binlog同步至数据中台。
2.  **数据加工**：中台完成清洗、去重、口径统一与多源融合，生成通话宽表、用户特征宽表。
3.  **实时数据消费**：外呼、意图识别等通话中场景直接调用对应服务，结果即时回写业务库；质检不走实时消费。
4.  **离线数据消费**：质检、分案、复盘、投诉研判、策略迭代等批量场景统一消费中台加工后的数据（质检须通话已结束且全文已齐）。
5.  **策略回流闭环**：迭代优化后的拨打策略、分层阈值、话术规则，经校验后同步回传统业务系统，驱动业务持续优化。

### 4.1 AI智能外呼对话系统

#### 4.1.1 产品定位

催收业务对外智能交互入口，承接账龄 M0/M1（`account_stage`）全量早期轻度逾期案件的自动化合规外呼与多轮对话，释放人工坐席产能，实现海量案件全覆盖触达。

#### 4.1.2 适用角色

系统管理员、运营主管、催收坐席、AI训练师

#### 4.1.3 核心功能需求

##### FR-OUT-001 合规自动外呼调度【P0】

- **前置条件**：数据中台已同步当日待催收案件，系统已配置外呼时段与频次规则
- **输入**：待外呼案件列表、外呼策略参数（允许拨打时段、最大重试次数、重试间隔）
- **处理逻辑**：
  1. 系统在允许时段内按优先级发起外呼，自动规避夜间、法定节假日等禁止拨打时段；
  2. 未接通案件按规则自动重试，超出当日最大重试次数标记为外呼失败，次日重新纳入调度；
  3. 同一用户当日拨打次数不超过上限，避免高频骚扰。
- **输出**：外呼任务执行记录、案件通话状态更新
- **异常场景**：
  1. 呼叫中心接口超时/报错：任务标记为待重试，计入下一轮调度，记录完整错误日志；
  2. 非允许时段触发外呼：系统直接拦截，不予执行；
  3. 案件数据缺失关键字段：自动跳过该案件，标记为数据异常待人工处理。

##### FR-OUT-002 实时语音交互能力【P0】

- **前置条件**：用户接通电话，通话链路正常建立
- **输入**：用户语音流、对话上下文
- **处理逻辑**：
  1. ASR流式转写用户语音为文本，支持中断打断；
  2. 基于对话上下文生成应答文本，通过TTS合成为语音播报；
  3. 支持多轮自由对话，维持上下文连贯性。
- **输出**：实时对话语音、对话文本记录
- **异常场景**：
  1. ASR连续3次识别失败：AI播报兜底话术“抱歉我没听清，请您再说一遍”，累计5次识别失败自动结束通话并标记异常；
  2. 用户静默超10秒：AI主动引导话术，累计20秒静默自动结束通话；
  3. TTS合成失败：播放预设兜底提示音，结束通话并记录异常。

##### FR-OUT-003 用户意图实时识别【P0】

- **前置条件**：通话过程中ASR持续返回用户文本
- **输入**：用户会话文本、对话上下文
- **处理逻辑**：识别用户核心意图，输出对应标签与置信度分数，意图枚举包括：还款意向、延期诉求、资金困难、拖延敷衍、拒绝沟通、情绪对抗、投诉意向。
- **输出**：意图标签、置信度分数，实时同步至对话流程
- **异常场景**：
  1. 识别置信度＜0.6：标记为「意图不确定」，不触发自动分流与标签归档；
  2. 识别服务超时/报错：不中断通话，标记为「识别失败」，通话结束后留存原始文本待离线补判。

##### FR-OUT-004 RAG合规话术赋能【P0】

- **前置条件**：RAG知识库服务正常运行
- **输入**：当前对话上下文、用户提问
- **处理逻辑**：
  1. 基于用户输入检索知识库中的合规话术、标准回复与优秀案例；
  2. 结合检索结果生成AI应答，所有输出必须符合合规要求，禁止超范围自由发挥；
  3. 应答前经过禁语关键词校验，拦截违规表述。
- **输出**：合规应答文本
- **异常场景**：
  1. RAG检索置信度＜0.6：禁止自由作答，输出固定兜底话术，标记为「知识库无匹配内容」；
  2. RAG服务不可用：自动降级为静态标准话术库，保障基础通话正常进行，记录降级日志。

##### FR-OUT-005 智能转人工调度【P0】

- **前置条件**：通话过程中识别到特定触发条件
- **输入**：用户意图标签、情绪等级、置信度
- **处理逻辑**：识别到复杂协商、激烈情绪对抗、明确投诉诉求时，自动触发转人工流程，将通话与案件信息同步至对应坐席。
- **输出**：转人工指令、案件与通话上下文同步至坐席端
- **异常场景**：
  1. 无空闲人工坐席：AI播报安抚话术，告知用户后续专人回电，结束通话后生成待跟进工单；
  2. 转人工链路失败：保留通话记录，生成人工回电任务。

##### FR-OUT-006 通话结果结构化输出【P0】

- **前置条件**：通话结束（用户挂断、AI结束、转人工）
- **输入**：全量对话文本、意图标签、通话时长、`record_url`（录音 URL，非独立文件实体）
- **处理逻辑**：
  1. 生成通话摘要，提炼核心沟通内容、用户诉求、跟进建议；
  2. 汇总所有意图、情绪、风险标签；
  3. 自动回填对应工单，关联通话 `session_id` 与 `record_url`（录音非独立实体）。
- **输出**：结构化通话记录、工单备注、标签数据
- **异常场景**：
  1. 摘要生成失败：保留原始对话文本，标记为「待人工补录」（**非 CI**，无对应错误码）；
  2. 工单回写失败：数据暂存本地队列，重试3次仍失败则告警通知人工处理。

### 4.2 AI录音质检系统（离线全量）

> 正式名/服务名：AI录音质检系统 · `qc-service`(8003)（命名口径见 §2.3 注）。详细设计见 [step2_需求PRD/DD-02-QUALITY-INSPECTION.md](step2_需求PRD/DD-02-QUALITY-INSPECTION.md) **V1.17**。R14/R10/红线 6 的**里程碑 M1**范围与 skip 以该文档 §5.2 为准（R14 不调 RAG 检索；红线 6 不在 qc 实现）。

#### 4.2.1 产品定位

事后合规审计与打分守门员。覆盖 AI 外呼与人工坐席**已结束**通话，实现 100% 离线全量质检、打分与风险复盘。通话进行中 qc **不介入**；事中拦截归外呼 Guardrails。

#### 4.2.2 适用角色

系统管理员、运营主管、质检专员（告警给事后主管，不弹通话页）

#### 4.2.3 核心功能需求

##### FR-QC-001 通话结束后全量离线质检【P0】

- **前置条件**：工作人员与客户通话已结束，且双向 ASR/对话全文已落库
- **输入**：已结束会话的对话文本（经数据中台 ODS 或回放接口）、通话基础信息
- **处理逻辑**：同时满足「通话已结束」+「全文已齐」才创建质检任务；文本未齐则等待 ETL/重试，不跑半通。不旁路监听、不每轮 ingest。
- **输出**：Redis 任务态（WAIT_TEXT / RUNNING / DONE）+ 落库后的质检记录（`qc_records`，含 `qc_status`）

**质检双状态机（禁止合并成一套枚举，权威 DD-02 §3.1）：**

| 层 | 枚举 | 说明 |
| --- | --- | --- |
| Redis `qc:job:{session_id}.status` | WAIT_TEXT / RUNNING / DONE | 通话业务键 `session_id`。WAIT_TEXT **禁止** INSERT `qc_records` |
| DB `qc_records.qc_status` | DONE / PENDING_REVIEW / REVIEWED / PARTIAL | **不落** WAIT_TEXT / FAILED / RUNNING。重试耗尽或崩溃才 PARTIAL |

流程图（通话结束 → turns 未齐则 WAIT_TEXT → 全文齐后离线质检）见 [step1/02](step1_项目总览/02_业务流程图_数据流程图.md)。

- **异常场景**：通话未结束或 turns 为空则拒绝质检（A2002/A2003）；不改写已结束通话的业务状态（非 CI：不测「不影响」语义，只验收错误码）。

##### FR-QC-002 离线违规检测与事后告警【P0】

- **前置条件**：FR-QC-001 全文就绪
- **输入**：整通对话文本、合规规则库、禁语库
- **处理逻辑**：
  1. 对整通做 AC + 规则 + LLM 检测（威胁恐吓、骚扰第三方、诱导承诺、辱骂等**坐席**违规）；
  2. 按风险等级分为高危、中危、低危三级；
  3. 高危写入告警台账，事后通知主管（列表 + 消息），**不**向通话工作台弹窗；
  4. 客户提及投诉、自杀、停呼、情绪激动 **不记工作人员违规**；仅当其后坐席仍催收/施压时记违规。
- **输出**：违规标签、时间戳、主管侧告警
- **异常场景**：LLM 熔断则只跑规则+敏感词，仍须出分。

##### FR-QC-003 合规打分与风险评级【P0】

- **前置条件**：通话结束
- **输入**：全量对话文本、违规记录
- **处理逻辑**：基于违规次数、严重程度计算单通通话合规分数与档位 `grade`；`risk_level` **独立于分数**（权威 DD-02：agent+high→high，否则累计扣分≥20→medium，否则 low）。禁止用分数切 `risk_level`。
- **输出**：合规分数、`grade`、风险等级、违规明细
- **异常场景**：打分规则缺失时默认标记为「待人工复核」。

##### FR-QC-004 违规台账与统计【P0】

- **前置条件**：质检完成
- **输入**：全量质检结果
- **处理逻辑**：自动汇总违规记录，支持按坐席、违规类型、时间维度统计。
- **输出**：违规台账、违规统计报表
- **异常场景**：数据统计异常时保留原始明细数据，不删除已落库记录（**非 CI**，无对应错误码）。

##### FR-QC-005 人工复核流程【P1】

- **前置条件**：生成疑似违规记录
- **输入**：疑似违规通话、质检专员操作
- **处理逻辑**：筛选高风险疑似违规通话推送人工复核，支持质检专员确认、驳回、修正判定结果。
- **输出**：复核结果、最终质检结论
- **异常场景**：复核结果与AI判定不一致，以人工结论为准，结果同步回流用于模型优化。

- **输入**：新版本知识内容

### 4.4 AI智能案件分层分案系统

#### 4.4.1 产品定位

业务智能调度中枢，实现逾期案件智能分层、用户风险打分、精准智能派单，最大化人效利用率。

#### 4.4.2 适用角色

系统管理员、运营主管、AI训练师

#### 4.4.3 核心功能需求

##### FR-CS-001 用户三维风险打分【P0】

- **前置条件**：数据中台已输出用户特征数据
- **输入**：用户历史还款行为、通话语义标签、情绪表现
- **处理逻辑**：从还款意愿、还款能力、投诉风险三个维度计算分数，输出综合风险等级。
- **输出**：三维风险分数、综合风险等级、打分依据
- **异常场景**：特征数据缺失时，基于已有字段打分并标记「数据不全」，不阻断分案流程。

##### FR-CS-002 案件智能分层【P0】

- **前置条件**：风险打分完成
- **输入**：账龄、风险等级、历史催收记录
- **处理逻辑**：自动将案件划分为账龄 M0/M1（`account_stage`）轻量案件、账龄 M2/M3 疑难案件、高对抗案件、失联风险案件四类。
- **输出**：案件分层标签
- **异常场景**：边界案件自动标记为「待人工确认」，默认归入保守层级。

##### FR-CS-003 人机智能分流【P0】

- **前置条件**：案件分层完成
- **输入**：案件分层标签、风险等级
- **处理逻辑**：轻量提醒类案件分配至AI外呼系统，疑难、高风险案件分配至人工坐席。
- **输出**：案件分流结果
- **异常场景**：AI外呼容量不足时，超额案件自动流转至人工坐席队列。

##### FR-CS-004 坐席智能匹配派单【P1】

- **前置条件**：案件分配至人工队列
- **输入**：案件类型、坐席能力标签、坐席负载
- **处理逻辑**：结合坐席擅长领域、历史回款表现、当前工作量，精准匹配派单。
- **输出**：坐席派单结果
- **异常场景**：无匹配坐席时，按轮询规则分配，标记为「默认分配」。

##### FR-CS-005 动态二次分案【P0】

- **前置条件**：通话结束，生成最新通话标签
- **输入**：原分层结果、最新通话意图与风险标签
- **处理逻辑**：基于最新通话结果重新评估案件等级，风险升级的案件自动流转至资深坐席。
- **输出**：二次分案结果、工单流转记录
- **异常场景**：分案规则冲突时，保留原分配结果，通知运营人工确认。

### 4.5 AI投诉异议智能研判系统

#### 4.5.1 产品定位

业务风险兜底模块，针对用户投诉、异议场景，实现全流程自动复盘、智能判责、取证与解决方案生成。

系统管理员、运营主管、质检专员

#### 4.5.3 核心功能需求

##### FR-CP-001 投诉工单关联取证【P0】

- **前置条件**：创建投诉工单
- **输入**：投诉工单信息、关联案件号（`case_ids[]`，主案件=`case_ids[0]`=`complaints.case_id`；支持多案件合并）

- **输出**：判责结论、判定依据、违规片段定位
- **异常场景**：证据不足无法判定时，标记为「待人工复核」。

- **输入**：违规判定结果、对话文本
- **处理逻辑**：精准截取违规话术片段、对应时间戳、上下文语境。
- **输出**：违规证据片段
- **异常场景**：无法精准定位时，返回整段相关对话供人工确认。

##### FR-CP-004 处置方案自动生成【P1】

- **前置条件**：判责完成
- **输入**：判责结论、投诉类型
- **处理逻辑**：基于合规知识库生成标准化回复话术、整改措施与处置建议。
- **输出**：答辩文案、整改方案
- **异常场景**：无匹配处置方案时，返回通用模板，标记为「需人工调整」。

##### FR-CP-005 投诉问题沉淀【P1】

- **前置条件**：投诉工单结案
- **输入**：全量投诉数据
- **处理逻辑**：统计高频投诉类型、高频违规点，输出风险整改报告。
- **输出**：投诉统计报表、整改建议
- **异常场景**：数据量不足时，仅输出已有数据统计，不做趋势推断。

- **异常场景**：场景匹配失败时，返回通用场景。
- **范围**：与 step1/01 非目标对齐；可留条文，**仅规划**，非里程碑 M1～M4 验收项。

##### FR-TR-005 运营报表自动生成【P1】

- **前置条件**：统计周期结束
- **输入**：周期内全量业务数据

- **输出**：运营报表
- **异常场景**：数据缺失时标注数据缺口，不生成错误结论。

## 5 全局非功能需求

### 5.1 安全与合规需求

1.  **数据脱敏**：客户手机号、身份证号、住址等敏感信息，页面展示与普通查询场景必须脱敏处理；仅高权限角色可查看完整信息，且操作留痕。
2.  **操作审计**：所有外呼配置、知识库修改、数据导出、权限变更操作，必须记录操作人、操作时间、操作内容，审计日志不可删除、不可篡改。
3.  **权限隔离**：不同角色严格按权限矩阵访问数据，禁止普通坐席越权查看他人案件、导出全量数据。
4.  **话术合规**：所有AI输出必须经过禁语库校验，禁止出现威胁、辱骂、诱导、骚扰第三方等违规表述。
5.  **数据留存**：通话录音、质检记录、工单数据按监管要求周期留存，到期可按规则归档或销毁。

### 5.2 稳定性与可靠性需求

1.  **服务降级**：各AI模块依赖的下游服务故障时，必须有降级兜底方案，保障核心业务不中断；例如RAG故障时AI外呼降级为静态话术库。
2.  **任务不丢失**：外呼任务、数据同步任务、离线任务执行失败必须有重试机制，异常数据标记留存，不得直接丢弃。
3.  **故障隔离**：七大子系统独立部署，单个模块故障不影响其他模块运行；实时链路故障不影响离线链路（**非 CI**，无对应错误码）。
4.  **异常兜底**：通话过程中出现静默、识别失败、服务超时等异常，必须有明确的结束或降级逻辑，不得出现通话卡死、无响应情况。

### 5.3 可维护性需求

1.  **配置化管理**：外呼频次、风险阈值、质检规则、分层阈值等业务参数，支持可视化配置，无需修改代码。
2.  **日志规范**：所有模块输出分级日志，错误日志必须包含模块、入参、异常信息、时间戳，支持快速定位问题。
3.  **模块解耦**：子系统间通过标准化接口交互，单个模块可独立升级、独立启停，不牵一发动全身。
4.  **知识库可迭代**：话术、规则、案例支持人工新增与修改，版本可追溯、可回滚。

### 5.4 性能需求

1.  **实时交互**：AI外呼单轮应答延迟≤1.5秒。质检无通话中 SLA（离线任务在全文就绪后执行）。
2.  **接口响应**：普通业务查询接口响应≤500ms，批量统计接口响应≤3秒。
3.  **并发能力**：外呼单节点 50 路；质检为离线任务吞吐（以 qc 里程碑为准），与外呼并发不是同一指标。
4.  **离线任务**：每日全量数据加工与报表生成，需在业务低峰期2小时内完成。

### 5.5 数据闭环需求

1.  **全链路可追溯**：单条案件从入池、分案、外呼、质检、工单更新、回款全流程数据可串联查询。
2.  **数据一致性**：核心业务字段全系统口径统一，避免多模块数据不一致。
3.  **异常可回溯**：AI决策结果必须附带判定依据，所有异常操作与失败任务留存日志与原始数据。
4.  **迭代可闭环**：业务效果数据可反向回流至数据中台，用于策略与模型优化。

### 5.6 业务口径定义（已确认，可配置）

> 本节所有参数默认值通过 `pydantic-settings` + `.env` 注入，运行时可调整，无需改代码。

#### 5.6.1 承诺还款率（PTP Rate）

`ptp_rate = 承诺还款(PTP)的接通通话数 ÷ 接通通话总数 × 100%`

- 以「接通通话」为统计分母（未接通、失败、失联不计入），反映在已建立有效沟通的通话中，实际取得客户承诺还款的转化效果。
- 承诺还款判定来源：`call_records.result = 'ptp'` 或 `intent_tags.intent_type = 'willing_to_pay' AND confidence >= 0.7`，二者任一满足即计入分子。

#### 5.6.2 置信度（Confidence）

全系统统一单一 `confidence` 字段（0-1），不区分来源。覆盖范围与阈值：

1. **意图识别**：用户意图模型输出的 `confidence`，< 0.6 标记为 `uncertain`，不触发任何自动分流。
2. **大模型话术生成**：AI 生成应答的 `confidence`，< 0.7 禁止直接回复，触发二次确认或转人工（宪法 1.1）。
3. **RAG 检索命中**：知识片段匹配 `score`（0-1），< 0.6 标记为"知识库无匹配内容"，调用方走兜底话术。
4. 取值校验：所有 `confidence` 字段必须在 Pydantic 层被 `Field(..., ge=0, le=1)` 限制。

#### 5.6.3 外呼对话轮次与第 13 轮分支判断（宪法 4.1）

- 强制最大对话轮次：**15 轮**。
- 第 13 轮触发判断：若「PTP 日期/还款金额/延期协商关键要素 仍未确认任一」→ 转接人工坐席；若关键业务结果已全部确认（如客户已明确 PTP）→ AI 播报结束语并结束通话。
- 辅助规则：连续 3 轮输出完全相同话术 → 立即转人工，不等待 13 轮。

#### 5.6.4 风险打分三维权重与风险等级阈值

- 三维权重（还款意愿 : 还款能力 : 投诉风险）= **0.4 : 0.3 : 0.3**。**仅用于分案**，不是质检 `risk_level`。
- 综合风险分数 = 意愿分 × 0.4 + 能力分 × 0.3 + (100 − 投诉风险分) × 0.3（投诉风险分越高越差，所以反向加权）。
- 分案综合风险等级阈值：
  - ≥ 80 → `low`（低风险）
  - 60 ~ 79 → `medium`（中风险）
  - < 60 → `high`（高风险）
- **质检**（权威 DD-02，禁止用分数切 `risk_level`）：
  - `grade`：由 `compliance_score` 与 `grade_thresholds` 决定（EXCELLENT≥90 / PASS≥80 / WARNING≥60 / SERIOUS<60）。
  - `risk_level`：独立于分数。合并后存在 agent+high → `high`；否则累计扣分≥20 → `medium`；否则 `low`。允许 `grade=PASS` 且 `risk_level=high`。

#### 5.6.5 合规外呼时段与频次控制

- 默认允许外呼时段：北京时间 **08:00 ~ 21:00**（工作日与节假日默认一致，如需对节假日单独限制可后续扩展配置）。
- 非允许时段 21:00 ~ 次日 08:00 禁止发起任何外呼请求，返回错误码 `A1001`。
- 同一用户（同一 `phone_hash`）每日最大拨打次数：**3 次**。
- 未接通重试间隔：**30 分钟**。
- 单案件最大重试次数：**3 次**，超过后标记「失联」并生成待跟进工单。
- 单节点最大并发呼叫数：**50 路**，超限请求排队等待。

#### 5.6.6 数据留存周期

- 通话录音：**6 个月**。
- 业务数据（案件/通话/标签/质检/工单/分案/投诉/复盘）：**2 年**。
- 操作审计日志与大模型调用日志：**5 年**（不可删除、不可篡改）。
- 到期处理：归档至冷存储（默认策略），或按监管要求销毁；留存周期为可配置项。

#### 5.6.7 MVP 首批接入范围

- 首批接入案件：账龄 **M0（逾期 1-30 天）/ M1（逾期 31-60 天）（`account_stage`）** 轻量案件，由 AI 外呼 100% 覆盖；账龄 M2/M3 疑难案件进入人工队列，后续**里程碑 M2** 分案系统上线后再逐步分流。
- 首批接入方式：通过种子数据脚本（100 案件 + 500 通话 + 2000 对话轮次）与离线导入工具喂入最小闭环，不依赖真实呼叫中心线路。
- 首批预期并发：单节点 50 路（与宪法一致），不做集群。

> 全部参数通过配置文件注入，运行时可调整，无需修改代码。详细定义见第 5.6 节「业务口径定义」。

1.  **外呼允许时段与频次规则**：允许时段 北京时间 08:00-21:00；同用户每日最多拨打 3 次；未接通重试间隔 30 分钟；单案件最大重试 3 次；单节点并发上限 50 路。
2.  **用户风险打分权重与分级阈值（分案三维分，≠ 质检 risk_level）**：还款意愿 : 还款能力 : 投诉风险 = 0.4 : 0.3 : 0.3；综合风险分数 ≥ 80→low、60~79→medium、<60→high。**质检** `grade` 由 `compliance_score` 决定（≥90 EXCELLENT / ≥80 PASS / ≥60 WARNING / <60 SERIOUS）；`risk_level` 独立：合并后存在 agent+high→high，否则累计扣分≥20→medium，否则 low。禁止用质检分数切 `risk_level`。
3.  **质检违规清单与分级标准**：分为 threat（威胁类/高危）、abuse（辱骂类/中危）、induce（诱导类/低危）三级；初始种子敏感词清单由 RAG 知识库模块给出，约 50-100 条，源自《催收自律公约》。
4.  **数据留存周期**：录音 6 个月，业务数据 2 年，审计与大模型调用日志 5 年；到期默认归档冷存储。
5.  **MVP 首批范围**：账龄 M0/M1（`account_stage`）轻量案件，通过种子数据 + 离线导入喂入，不依赖真实呼叫线路；首批单节点并发 50 路。

## 附录B 项目简历描述

**项目名称**：基于大模型的催收行业七维AI智能赋能生态系统

**项目简介**：基于一线电话催收业务实操经验，针对传统催收高度依赖人工、合规风险高、人力成本昂贵、数据无法沉淀、策略迭代滞后等行业痛点，自主设计并搭建传统业务底座+七大AI微服务+RAG全局知识大脑+数据中台的企业级人智协同智能催收生态系统。项目不推翻原有业务架构，以AI能力赋能传统流程，实现海量逾期案件自动化触达、全量通话合规风控、智能案件调度、客诉智能判责、团队能力智能化迭代，构建全链路数据自闭环，解决传统催收“效率低、成本高、风险大、迭代慢”的核心痛点。

**技术栈**：Python、FastAPI微服务、LangGraph、RAG检索增强、多模态解析、Milvus向量库、ASR/TTS语音AI、Prompt工程、模型微调、数据中台ETL、特征工程、异步任务调度

**核心成果**：

1.  搭建四层企业级架构，拆分7大解耦AI子系统，明确实时链路与离线链路边界，AI仅负责认知判断，传统系统执行业务流程，规避大模型幻觉带来的业务风险。
2.  构建RAG多模态全局知识库，整合催收法规、合规禁语、标准话术、优质催收案例；**MVP/里程碑 M1 以 Milvus 稠密检索**为全系统提供知识支撑，ES BM25/RRF/rerank 为二期/可选，统一AI应答标准、杜绝违规输出。
3.  落地AI智能外呼与离线全量质检：账龄 M0/M1（`account_stage`）自动化合规外呼，出口由 Guardrails 拦截；通话结束后 100% 全量质检、事后风险告警与自动打分，替代传统抽样漏检。
4.  设计AI智能分层分案引擎，基于用户语义特征、历史行为、情绪风险三维打分，实现人机智能分流与坐席精准派单，优化人力资源利用率，聚焦疑难高价值案件攻坚。
5.  搭建投诉研判与复盘培训体系，实现客诉自动回溯取证、智能判责、方案生成；自动沉淀全量通话优劣案例，实现团队能力批量迭代。
6.  搭建催收专属数据中台，完成多源数据汇聚清洗、宽表建模、特征工程、样本治理，离线迭代最优拨打与话术策略并回流业务系统，实现业务数据自闭环、自进化。
